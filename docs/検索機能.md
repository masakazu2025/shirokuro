# 検索機能

## 背景

社内で実際に使われている2つのツールの使い方を統合することを目指す。

- **①閲覧特化(自分が使用)**: IP単一+日付+取引番号で検索。最新の取引を番号を知らなくても探せる。POS取引終了後に「最新」ボタンを連打して確認する使い方。自動採取が裏で動くため後からゆっくり整理できるが、不要なもの(画像等)も採取してしまうのが難点
- **②採取特化(別の担当者が使用)**: IP複数+現在時刻からN秒遡って、ヒットしたものをすべて取得。取引直後に即採取する使い方(スライダーで秒数指定、常時表示)。閲覧性を犠牲にしているが、必要なものだけ確実に採れる

①を採用しつつ、②の即時性・確実性も取り込む「良いとこ取り」が方針。

## 最終系(ゴール)

### 端末選択
- 店舗で絞り込んでからレジNoを選択できる、階層的な選び方(理想形)
- POS店舗サーバのレジマスタから現在の情報を取得・登録する仕組み(将来検討)
- ドロップダウン+チェックボックスで複数選択。IPを主に表示、レジNoは補足情報として表示
- ドロップダウン最下部に「詳細指定」→モーダルで自由入力のIP・レジNo指定(未登録端末や、過去のレジNo変更への対応)
- 端末を1つも選択していない場合は検索不可(空検索・巨大な結果セットの事故防止)

### 日時
- クイック指定: 当日 / 直近N秒(スライダー、常時表示) / カスタム範囲
- デフォルトは単一の日付(当日)。▼ボタンで範囲指定に展開でき、展開状態は維持できる
- より複雑な指定が必要な場合のモーダル(現状ニーズなし、保留)
- 「直近N秒」は②(取引直後の即時採取)向け。スライダー操作での即検索も検討

### 取引番号
- 常時表示のシンプルな範囲指定(from〜to)
- 複数端末選択時はグレーアウト(レジごとに番号体系が異なるため)

### 検索結果
- 自動更新: 検索条件全体(端末選択含む)が前回と同一なら差分取得(最後に見た`created_at`以降)、条件が変われば全件取り直し
- NEW表示: 差分取得の結果はすべて新着なので、追加の比較ロジックなしで実現できる
- 並び替え: フロント側で保持している配列をソートするだけ(バックエンドの`ORDER BY`は不要)
- ページネーション: フロントのメモリ内配列をスライスして描画。バックエンドへの追加リクエストは発生しない
- バックエンドの安全弁(上限10000件、[[project_search_use_cases]]参照)に達した場合は、一覧を描画せず「絞り込んでください」のメッセージを表示

### 状態の持ち方
- 好み(モード)の記憶: 日時の展開状態、クイック指定のモード → localStorage(端末・ブラウザに紐づく好みなので)
- 実際の検索値: URLクエリパラメータ(画面遷移をしても検索状態が失われないようにするため。取引データ画面⇄画像データ画面の行き来が多いため重要)

## 実装ステップ

1. バックエンドAPI(検索クエリの拡張、10000件上限) ✅ 完了(`feature/search`ブランチ)
2. フロントエンド: 端末選択(候補は`Transaction`テーブルからDISTINCTで動的取得。初回デモでは`Terminal`テーブルは使わない)
3. フロントエンド: 日時クイック指定(当日/カスタム範囲)、URLクエリパラメータとの同期
4. フロントエンド: 一覧のページネーション表示
5. フロントエンド: 自動更新・差分取得・NEW表示
6. (保留) 直近N秒スライダー・即検索
7. (保留) 端末詳細指定モーダル(自由入力のIP・レジNo)
8. (将来検討) 店舗→レジの階層選択、POS店舗サーバのレジマスタ連携
